建立消息协议--这是客户端与服务端之间通信的“语言”

### 1. 消息格式设计

每条消息的结构是：
┌──────────────────┬─────────────┬──────────────────┐
│  消息总长度(4字节) │ 消息类型(1字节) │    消息体(变长)    │
└──────────────────┴─────────────┴──────────────────┘

- 消息总长度：告诉接收方"这条消息还剩多少字节要读"，防止粘包/拆包
- 消息类型（MessageType）：一个数字，标记这条消息是"玩家移动"还是"玩家交互"等
- 消息体：具体的数据，不同类型的消息体不同

### 2.涉及到的类

#### 2.1. MessageType

#### 2.2. NetworkMessage

网络消息的序列化/反序列化工具类。
每条消息格式：[4字节消息体长度] [1字节消息类型] [变长消息体]
使用方式：

```csproj
//发送：byte[] data = NetworkMessage.Create_PlayerPosition(1, 2.5f, 0, -3f, 90f);
//接收：先用 ReadHeader() 读出长度和类型，再根据类型调用对应的 Parse_xxx()
```

## 工作流程：操作台交互

### 流程一：普通操作台（ClearCounter、TrashCounter、ContainerCounter 等）

```
玩家按E键
  ↓
PlayerController.DoInteract(true)
  ├─ _selectedCounter.Interact(this)          ← 本地立即执行（物品转移，即时反馈）
  └─ SendInteractionResultToServer()          ← 上报结果给服务器
       ↓
  C2S_InteractResult(counterId, counterItem, playerItem)
       ↓
服务器 HandleInteractResult()
  ├─ 更新 counter.ItemIndex / player.HeldItemIndex
  └─ BroadcastAll( InteractionSync(counterId, counterItem, playerId, playerItem) )
       ↓
所有客户端收到 InteractionSync：
  ├─ CountersManager → ApplyCounterState()    ← 更新操作台上的物品（带去重检查）
  └─ NetworkPlayer → ApplyHeldItem()          ← 更新对应玩家手中的物品
```

### 流程二：进度类操作台副交互（CuttingCounter 按空格切菜）

```
玩家按空格
  ↓
PlayerController.DoInteract(false)
  ├─ 检测到 IsProgressCounter == true
  ├─ _selectedCounter.InteractAlternate(this) ← 本地只播放动画/音效，不计进度
  └─ SendInteractAlternate(counterId)         ← 只发 counterId，不含物品状态
       ↓
  C2S_PlayerInteractAlternate(counterId)
       ↓
服务器 HandlePlayerInteractAlternate()
  └─ HandleCuttingInteract()
       ├─ CutCount++
       ├─ BroadcastAll( CounterProgressSync(counterId, progress) )
       └─ 切完时重置计数
            ↓
所有客户端收到 CounterProgressSync：
  └─ CountersManager → CuttingCounter.ApplyServerCutProgress()
       ├─ 更新进度条UI
       └─ progress>=1 时执行物品转换（销毁原料→生成成品）
```

### 流程三：PlateCounter 盘子同步（新架构见下方【盘子网络同步】章节）

```
服务器后台循环（每50ms）：
  └─ UpdateCounters() → PlateCounter 分支
       ├─ 计时满4秒 且 plateCount < PLATE_MAX
       ├─ PlateCount++，Plates.Add(plateId)
       ├─ 创建 ServerPlate（分配全局唯一 plateId，owner=该操作台）
       └─ BroadcastAll( PlateSpawned(counterId, plateId) )
            ↓
所有客户端收到 PlateSpawned：
  └─ PlateManager.OnPlateSpawned()
       ├─ 创建失活的 PlateKitchenObject（作为 PlateManager 子对象）
       ├─ SetNetworkId(plateId)，登记到 Dictionary<plateId, plate>
       ├─ 放入该操作台的池子 counterPlatePools
       ├─ SendPlateRegisterSO(plateId, soIndex) ← 上报SO索引供FullSync恢复
       └─ PlateCounterVisual 增加一个视觉盘子（数量栈）
```

## 工作流程：盘子网络同步（PlateKitchenObject）

### 0. 核心设计思想

| 思想 | 说明 |
|------|------|
| **服务器权威** | 服务器生成 `ServerPlate` 并分配全局唯一 `plateId`，客户端从不自己分配 |
| **盘子是独立实体** | 盘子有独立网络身份，配料/持有者数据**不依附于玩家或操作台** |
| **PlateManager 中央管理** | 客户端 `PlateManager` 是唯一权威：唯一登记表 + 池子 + 移动 |
| **池化 + 失活** | 服务器生成时，客户端创建**失活**的 PlateKitchenObject 作为 PlateManager 子对象，等待分配 |
| **视觉解耦** | PlateCounter 上的盘子数量由 `PlateCounterVisual` 独立表现（视觉栈），与实体解耦 |
| **增量同步** | 配料添加/移除各用一条消息（plateId + ingredientIndex），幂等（TryAdd/Remove 自带去重） |

### 1. 盘子相关消息协议

#### 服务端 → 客户端

| 消息类型 | 值 | 内容 | 用途 |
|---------|----|------|------|
| `PlateSpawned` | 18 | counterId, plateId | 通知所有客户端新盘子出现 |
| `PlateOnwerSync` | 19 | plateId, ownerType, ownerId, ingredients[] | 盘子持有者变更广播 |
| `PlateAddIngredient` | 20 | plateId, ingredientIndex | 盘子添加配料广播 |
| `PlateDestroy` | 21 | plateId | 盘子销毁广播 |
| `PlateRemoveIngredient` | 22 | plateId, ingredientIndex | 盘子移除配料广播 |
| `RemotePlate` | 17 | counterId, plateId | 盘子从操作台被拿走（减视觉） |

#### 客户端 → 服务端

| 消息类型 | 值 | 内容 | 用途 |
|---------|----|------|------|
| `C2S_PlateOnwerSync` | 110 | plateId, ownerType, ownerId, ingredients[] | 上报盘子持有者变更 |
| `C2S_PlateAddIngredient` | 111 | plateId, ingredientIndex | 上报盘子添加配料 |
| `C2S_PlateDestroy` | 112 | plateId | 上报盘子销毁 |
| `C2S_RegisterPlateSO` | 113 | plateId, soIndex | 上报盘子的 SO 索引（FullSync 恢复用） |
| `C2S_RemotePlate` | 114 | counterId, plateId | 上报盘子从操作台被拿走（数量变化） |
| `C2S_PlateRemoveIngredient` | 115 | plateId, ingredientIndex | 上报盘子移除配料 |

### 2. 盘子生成

```
服务器：
  └─ UpdateCounters()（每50ms后台循环）
       └─ PlateCounter 计时满4秒 且 PlateCount < PLATE_MAX
            ├─ PlateCount++
            ├─ Plates.Add(plateId)                    ← 记录在该操作台上的盘子ID
            ├─ new ServerPlate(plateId) { OwnerType=1, OwnerId=counterId, SoIndex=0 }
            ├─ plates[plateId] = newPlate
            └─ BroadcastAll( PlateSpawned(counterId, plateId) )
                 ↓
所有客户端：
  └─ PlateManager.OnPlateSpawned(counterId, plateId)
       ├─ Instantiate(plateSO.prefab, PlateManager.transform)   ← 作为 PlateManager 子对象
       ├─ SetNetworkId(plateId)，SetOwner(1, counterId)
       ├─ SetActive(false)                                      ← 失活，进入池子
       ├─ plates[plateId] = plate                               ← 唯一登记表
       ├─ counterPlatePools[counterId].Add(plate)              ← 放入操作台池子
       ├─ SendPlateRegisterSO(plateId, soIndex)                 ← 上报SO，供FullSync恢复
       └─ plateCounter.OnPlateSpawned?.Invoke()
            └─ PlateCounterVisual：视觉栈增加一个盘子模型
```

### 3. 盘子全量更新（FullSync）

```
触发时机：新客户端连接时（AssignPlayerId 后立即发送）

服务器 SendFullSyncToClient：
  └─ Create_FullSync(players, counters, plates)
       └─ plates 部分：plateCount + [plateId + ownerType + ownerId + soIndex + ingredientCount + ingredients[]] × N

客户端 NetworkManager.FullSync 分支：
  └─ PlateManager.RestorePlatesFromFullSync(plates)
       ├─ 跳过"已存在"的盘子（与实时 PlateSpawned 竞争）
       ├─ 跳过本地玩家自己的盘子（本地玩家刚生成，无手持）
       ├─ ownerType == 1（操作台上）：
       │    ├─ PlateCounter → SpawnPooledPlate（池化 + 视觉）
       │    └─ 其他操作台 → 激活 + 挂到操作台 + 应用配料
       └─ ownerType == 0（远程玩家手上）：
            └─ NetworkPlayer.RestoreHeldPlate(plateId, soIndex)
                 └─ 生成盘子 → 设置 NetworkPlateId → 挂到玩家手 → 应用配料
```

### 4. 玩家获取盘子

```
玩家在 PlateCounter 前按 E（空手）
  ↓
PlateCounter.Interact(player)
  └─ PlateManager.GivePlateToPlayer(counter, player)
       ├─ 校验：玩家空手 + 池子非空
       ├─ 出池（LIFO，取最近生成的盘子）
       ├─ SetActive(true)                                        ← 激活
       ├─ SuppressOwnerSync = true → SetKitchenObjectParent(player) → 恢复   ← 抑制回声
       ├─ SetOwner(0, playerId)
       ├─ counter.OnPlateRemove?.Invoke()                        ← 视觉栈减一个
       ├─ SendPlateOwnerSync(plateId, 0, playerId, ingredients[]) ← 归属变化
       └─ SendRemotePlate(counterId, plateId)                     ← 数量变化

服务器：
  ├─ HandlePlateOwnerSync：更新 ServerPlate.OwnerType/OwnerId → BroadcastExcept(PlateOwnerSync)
  └─ HandlePlateRemote：Plates.Remove(plateId) → PlateCount-- → BroadcastExcept(RemotePlate)

其他客户端：
  ├─ 收到 PlateOwnerSync → PlateManager.OnPlateOwnerSync
  │    ├─ 找到盘子 → MovePlateToOwner(plate, 0, playerId)
  │    │    ├─ 与当前持有者解绑（清空 NetworkPlayer.heldKitchenObject）
  │    │    └─ NetworkPlayer.AttachHeldPlate(plate)：激活 + 挂到玩家手 + 登记
  │    └─ 应用配料（ApplyOwnerSyncData）
  └─ 收到 RemotePlate → PlateManager.OnRemotePlateRemoved
       └─ PlateCounterVisual：视觉栈减一个
```

### 5. 盘子放置 / 拿起（持有者变更）

```
玩家把盘子放到 ClearCounter（空台）：
  ClearCounter.Interact
    └─ plate.SetKitchenObjectParent(counter)          ← 本地立即移动
         └─ PlateKitchenObject.OnKitchenObjectParentChanged
              └─ SendPlateOwnerSync(plateId, 1, counterId, ingredients[])   ← 单次上报

服务器 HandlePlateOwnerSync → 更新 owner → BroadcastExcept(PlateOwnerSync)

其他客户端 PlateManager.OnPlateOwnerSync：
  └─ MovePlateToOwner(plate, 1, counterId)
       ├─ 若之前在玩家手上 → 先解绑（DetachHeldPlate，清空 heldKitchenObject）
       ├─ SetActive(true)
       └─ SetKitchenObjectParent(counter)（抑制回声）

⚠️ 关键点：普通操作台的物品同步（CounterAddIngredient → ApplyCounterState）对盘子
   必须"不销毁、不生成"（盘子实体由 PlateManager 移动），否则会把刚放上去的盘子销毁。
```

### 6. 盘子添加配料

```
本地玩家用盘子装操作台配料（ClearCounter/CuttingCounter/BoilingCounter）：
  ↓
PlateManager.PlateAddIngredient(plate, so)
  ├─ 校验：plate 已登记（plates.ContainsKey(plateId)）
  ├─ plate.TryAddIngredient(so)                    ← 本地添加 + 视觉更新
  └─ 成功 → SendPlateAddIngredient(plateId, ingIdx)

服务器 HandlePlateAddIngredient：
  ├─ 校验盘子存在 + 配料不重复
  ├─ ServerPlate.Ingredients.Add(ingIdx)
  └─ BroadcastAll(PlateAddIngredient(plateId, ingIdx))

其他客户端 PlateManager.OnPlateIngredientSyncReceived：
  └─ plates[plateId].TryAddIngredient(so)          ← 幂等（重复自动拒绝）
```

### 7. 盘子移除配料（倒入 BoilingCounter）

```
本地玩家把盘子配料倒入 BoilingCounter：
  BoilingCounter.Interact（玩家持盘 + 台子空）
    └─ foreach(ingredient in plateIngredients)
         ├─ TryAddIngredients(ingredient)          ← 操作台接受该配料
         ├─ PlateManager.PlateRemoveIngredient(plate, ingredient)   ← 网络模式
         │    ├─ plate.RemoveIngredient(so)         ← 本地移除 + 视觉更新
         │    └─ SendPlateRemoveIngredient(plateId, ingIdx)
         ├─ SendCounterAddIngredient(counterId, ingIdx)             ← 操作台加配料
         └─ TryStartRecipeIfPossible()              ← 尝试开始煮

服务器：
  ├─ HandlePlateRemoveIngredient：ServerPlate.Ingredients.Remove(ingIdx) → BroadcastAll(PlateRemoveIngredient)
  └─ HandleCounterAddIngredient：更新操作台 → BroadcastAll(CounterAddIngredient)

其他客户端 PlateManager.OnPlateIngredientRemovedReceived：
  └─ plates[plateId].RemoveIngredient(so)          ← 盘子上的配料消失
```

### 8. 盘子销毁（仅 DeliveryCounter）

```
DeliveryCounter.Interact（玩家持盘）：
  ├─ DeliveryManager.DeliveRecipe(plate)
  ├─ SendPlateDestroy(plateId)                      ← 上报服务器
  └─ 本地 DestroySlef()

服务器 HandlePlateDestroy：
  ├─ plates.Remove(plateId)                         ← 从登记表移除
  └─ BroadcastAll(PlateDestroy(plateId))

其他客户端 PlateManager.OnPlateDestroyReceived：
  ├─ 若在某玩家手上 → DetachHeldPlate（清空 heldKitchenObject）
  ├─ 若在某操作台上 → ClearKitchenObject
  ├─ plates.Remove(plateId)，从池子移除
  └─ Destroy(plate.gameObject)

⚠️ TrashCounter 不能销毁盘子：Interact 中 TryGetPlate 直接 return
```

### 9. 涉及到的类

| 类 | 职责 |
|----|------|
| `ServerPlate`（服务端） | 盘子实体：PlateId、Ingredients、OwnerType、OwnerId、SoIndex |
| `PlateManager`（客户端） | 中央管理：唯一登记表 `Dictionary<plateId, plate>`、池子、移动、FullSync 恢复 |
| `PlateKitchenObject` | 盘子组件：NetworkPlateId、OwnerType/OwnerId、配料增删、SuppressOwnerSync 防回声 |
| `PlateCounter` | 提供盘子 SO、触发 `OnPlateSpawned/OnPlateRemove` 事件 |
| `PlateCounterVisual` | 独立视觉栈：数量增减时增删视觉盘子模型 |
| `NetworkPlayer` | 远程玩家手持盘子：AttachHeldPlate / DetachHeldPlate / RestoreHeldPlate |
| `CountersManager` | 普通操作台物品同步（对盘子特殊分支：不销毁不生成） |

### 10. 盘子同步的关键设计原则

| 原则 | 说明 |
|------|------|
| **服务器分配 ID** | 客户端只在上报 `PlateSpawned` 时创建实体并登记，不自行分配 ID |
| **唯一实体移动** | 盘子实体只有一个，持有者变更时**移动**而非重新生成 |
| **抑制回声** | 收到 owner sync 移动盘子时置 `SuppressOwnerSync`，避免把服务器消息再发回去 |
| **解绑防残留** | 盘子离开玩家/操作台时必须清空 `NetworkPlayer.heldKitchenObject`，否则会被 PlayerInteract 销毁 |
| **配料增量 + 幂等** | 添加/移除各一条消息，`TryAddIngredient/RemoveIngredient` 自带去重 |
| **PlateCounter 视觉与实体解耦** | 池化盘子失活，视觉数量由 PlateCounterVisual 独立表现 |
| **销毁只走 DeliveryCounter** | TrashCounter 拒绝销毁盘子，防止服务器与本地状态不一致 |
| **FullSync 防重复** | 恢复时跳过已存在盘子，避免与实时 PlateSpawned 竞争产生重复 |

---

### 关键设计原则

| 原则 | 说明 |
|------|------|
| **InteractionSync 是原子消息** | 一次交互 = 一条消息，同时携带操作台和玩家两边的最终状态 |
| **本地预测 + 服务器确认** | 简单操作台先本地执行（即时反馈），服务器回显时去重跳过 |
| **进度由服务器驱动** | CuttingCounter/StoveCounter 等进度操作台，本地不自己计时 |
| **去重检查** | `IsAlreadyInTargetState()` 防止服务器回显导致重复创建/销毁物品 |

## 第十步：服务器权威的订单同步（Delivery / Recipe）

订单（Recipe）的**裁决**由**服务器权威**管理：服务器生成订单、校验交付、维护分数；
而**内容**（配方表）由客户端连接后上报、服务器校验注册——**内容可以来自客户端，但结果只能服务器拍板**。
客户端只负责展示订单、上报配方和提交交付请求，**不做任何订单校验**。

### 1. 消息协议（新增/修复）

| 方向 | 类型 | 消息体 | 说明 |
|------|------|--------|------|
| S→C | `RecipeSpawned = 8` | `recipeIndex(int)` | 服务器生成新订单（RecipeListSO 索引） |
| S→C | `RecipeCompleted = 9` | `recipeIndex(int)` | 订单完成（交付成功） |
| S→C | `RecipeFailed = 10` | 空 | 交付失败 |
| S→C | `ScoreUpdate = 11` | `score(int)` | 分数（累计成功交付数） |
| S→C | `FullSync = 13` | ... + `recipeCount(int) + [recipeIndex(int)]*N` | 追加等待中的订单，支持中途加入恢复 |
| C→S | `C2S_DeliveryRequest = 117` | `plateId(int)` | 客户端提交交付请求 |
| C→S | `C2S_RegisterRecipes = 118` | `recipeCount(int) + [ingredientCount(int) + [ingredientIndex(int)]*N] * N` | 客户端上报配方表（连接后注册） |

> ⚠️ 修复：服务器原 `Create_RecipeCompleted` 错误地打成 `RecipeSpawned` 类型，已改为 `RecipeCompleted`；并补上缺失的 `Create_RecipeSpawned`。

### 2. 配方表注册（内容由客户端提供）

```
客户端连接成功（OnNetworkConnected）
  └─ DeliveryManager.SendRegisterRecipes()
       └─ 遍历本地 RecipeListSO.asset（顺序 = recipeIndex 空间）
            └─ 每条配方 → KitchenObjectRegistry 索引数组（注册表外原料得 -1）
                 └─ C2S_RegisterRecipes(配方表)
                      ↓
服务器 HandleRegisterRecipes：
  ├─ 防御性校验：配方数 1..32、单配方配料数 1..6、配料索引 ∈ [-1, KitchenObjectRegistry.Count)
  ├─ 校验通过 → RecipeRegistry.RegisterRecipes()（第一个上报者优先，与 C2S_CounterRegister 一致）
  └─ 校验失败 / 已注册 → 拒绝并告警
```

- **多场景支持**：客户端在切换场景 / 关卡时重新上报当前场景的配方表即可，服务器以"第一个上报者"为准，无需为每个场景写死配置。
- **内容 vs 权威**：配方内容由客户端上报，但订单的生成时机、交付校验（用服务器 `ServerPlate.Ingredients`）、计分仍全部在服务器执行——状态层依旧是服务器权威。

### 3. 服务器侧

| 类 | 职责 |
|----|------|
| `RecipeRegistry`（重构） | 配方注册表：由客户端上报 + 服务端校验注册（`RegisterRecipes`，线程安全）；提供 `Matches()` 校验 |
| `ServerDeliveryManager`（新） | 权威订单状态机：等待订单列表、分数、生成计时（4s/单，上限 4）、`HandleDeliveryRequest(plateId)` 校验并广播 |
| `GameServer` | 接入：初始化 deliveryManager、处理 `C2S_DeliveryRequest` / `C2S_RegisterRecipes`、更新循环刷单、FullSync 携带订单、`StartNewGame()` 重置 |
| `ServerGameManager` | 游戏进入 `GamePlaying` 时调用 `server.StartNewGame()` 重置订单并立即刷第一单 |

```text
服务器生成订单：
  UpdateCounters（仅 GamePlaying）→ ServerDeliveryManager.Update
    └─ 每 4s 且等待 < 4 且 配方表已注册 → 随机配方 → BroadcastAll(RecipeSpawned(recipeIndex))

交付流程（服务器权威）：
  DeliveryCounter.Interact（玩家持盘）
    └─ DeliveryManager.DeliveRecipe(plate) → SendDeliveryRequest(plateId)
         └─ 服务器 HandleDeliveryRequest(plateId)
              ├─ TryGetPlateIngredients(plateId)   ← 取服务器自己维护的盘子配料，不信任客户端
              ├─ 与等待订单逐条 Matches() 校验
              ├─ 成功 → 移除订单 + 分数+1
              │        BroadcastAll(RecipeCompleted + ScoreUpdate)
              ├─ 失败 → BroadcastAll(RecipeFailed)
              └─ DestroyPlate(plateId)              ← 服务器销毁盘子并广播（替代客户端 SendPlateDestroy）
```

### 4. 客户端侧

| 类 | 变更 |
|----|------|
| `DeliveryManager` | 连接成功后上报配方表（`SendRegisterRecipes`）；订阅 `OnRecipeSpawned/OnRecipeCompleted/OnRecipeFailed/OnScoreUpdate/OnRecipeFullSync`；`DeliveRecipe` 只发 `SendDeliveryRequest(plateId)`；`recipeListSO` 空时从 `Resources/RecipeListSO` 加载 |
| `NetworkManager` | 新增 `SendDeliveryRequest`、`SendRegisterRecipes`、`FullSyncRecipes` 缓存；FullSync 解析订单并触发 `OnRecipeFullSync` |
| `NetworkMessage` | 新增 `Create_DeliveryRequest`、`Create_RegisterRecipes`；`Parse_FullSync` 追加 `out int[] recipes`（向后兼容旧消息） |
| `DeliveryCounter` | 移除重复的 `SendPlateDestroy`（交付后由服务器统一销毁） |

### 5. 关键设计原则

| 原则 | 说明 |
|------|------|
| **内容由客户端提供，裁决由服务端执行** | 配方表客户端上报、服务端校验注册；订单生成/交付校验/计分全部在服务端 |
| **订单由服务器生成** | 客户端不本地刷单，所有客户端看到同一份订单（服务器广播） |
| **校验不信任客户端** | 交付校验用服务器 `ServerPlate.Ingredients`，客户端只传 plateId |
| **交付即消费** | DeliveryCounter 一定消耗盘子：无论成功失败，服务器统一销毁盘子并广播 `PlateDestroy` |
| **中途加入可恢复** | FullSync 携带等待订单，客户端 `RestoreWaitingRecipes` 重建订单 UI |
| **索引空间一致** | `recipeIndex` 对应客户端 `RecipeListSO.asset` 顺序；配料索引对应 `KitchenObjectRegistry`（两端已核对一致） |
| **防错过事件** | `NetworkManager.FullSyncRecipes` 缓存 + `DeliveryManager.OnEnable` 主动补齐（面板/管理器晚加载时） |
| **防御性校验** | 服务器拒绝非法配方内容（数量上限、索引越界），防止篡改客户端塞入异常数据 |

### 6. ⚠️ 数据一致性提醒

客户端 `RecipeListSO.asset` 中 Burger/CheeseBurger/MEGABurger/Salad 引用的原料
（MeatBurned、Bread、CheeseSlices、CabbageSlices、TomatoSlices）**不在 `KitchenObjectRegistry` 中**，
因此这些配方上报给服务器时会得到索引 `-1`。服务器允许注册（用于保持 `recipeIndex` 对齐），
但 `Matches()` 对含 `-1` 的配方永远返回 false——这些订单在实际游戏中无法交付。
真正可交付的订单是 `FishSoup`（索引 4）和 `Xiaolonbao`（索引 5）。
若日后把上述原料加入注册表，**无需改服务器**，客户端重新上报即可生效（内容由客户端驱动）。
