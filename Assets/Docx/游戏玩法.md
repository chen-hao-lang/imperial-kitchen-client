# 游戏玩法

## 盘子的所有逻辑
### 涉及类：
服务器：
- ServerPlate：
属性：
- int PlaterId //盘子的唯一ID
- List<int> Ingredients // 存储盘子上的所有配料
- byte OwnerType //盘子的拥有者类型，0为玩家，1为操作台
- int ownerId // 盘子当前的拥有者Id

- PlateCounter
属性：
- int PlateCount //当前操作台上的盘子数量
- float PlateSpawnTimer // 盘子生成计时器
- int PLATE_MAX // 最多能生成的盘子数量
- float PLATE_SPAWN_INTERVAL //盘子生成间隔

### 逻辑
1. 盘子的生成：
- 由服务器生成，当服务器生成时，生成ServerPlate，分配ServerPlate的id，同时分配拥有者属性，记录生成的盘子
- 通知所有客户端，消息为（盘子操作台id，生成的盘子id）
- 客户端收到消息后，PlateManager生成盘子PlatekitchenObject，为其分配PlateId,并通知对应的CounterId的操作台在视觉上生成台子。PlateManager将生成的PlateKitchenObject作为自己的子对象，并将其设为失活状态，将其加入到列表Plates

2. 全量更新
- 当客户端A先连接时，此时服务器端已经开始生成盘子，如果客户端B晚连接，那么就会造成两边盘子不一致的问题。所以当客户端B连接时，服务器下发当前的PlaterCounter的数量和所有ServerPlate的属性。客户端收到消息后，根据消息内容更新PlateCounter的视觉数量，并通过PlateManager更新所有盘子的状态
- 该全量更新为只属于盘子类的全量更新，不涉及玩家、其他操作台
- 全量发生时，由客户端的PlateManager去处理玩家和操作台上的东西

3. 玩家获取盘子
- 当玩家与PlateCounter交互想要获取盘子时，由plateManager分配盘子给玩家，并通知服务器当前的盘子属性发生改变，以及操作台数量发生改变。服务器再通知其他客户端进行同步。

4. 盘子添加配料

5. 盘子销毁
- 只有操作台DeliveryCounter能够销毁盘子

## 工作流程
1. 启动服务器
2. 客户端连接
3. 服务器收到客户端连接，为客户端分配玩家id（Connect）
4. 服务器再初始化客户端
