### 查出的 5 个「不是版本号、但同样会让热更静默失效」的点
1. 🔴 **分钟级粒度** → 同一天同一分钟内重建同一包会拿到**完全相同的版本号**；已装过该版本的客户端**永远不会再拉取**（沙盒清单路径含版本号，`File.Exists` 命中即跳过远端）。跨天不会撞。
2. 🟡 **不该上传的 3 类文件**：每个版本目录里除三件套 + bundle 外还有 `{包名}_{版本}.report`、`buildlogtep.json`、`link.xml`。客户端**永不请求**，只会白耗流量 + 把完整资源依赖清单公开。其中后两者在 5 个包里**同名**，平铺合并会互相覆盖。当前 `CdnUpload/PC/v1.0` 有 **209** 个文件 = 189 bundle + 15 三件套 + 5 个 `.report`；**正确数量应是 204**。
3. 🟡 **内置与 CDN 同版本**（这是对的），含义是：只改资源不重新打包 = 客户端毫无变化。必须「改资源 → 重新构建（新版本号）→ 上传」三步齐全。
4. ⚪ `Library/yoo/{包名}/ManifestFiles/` 里躺着 `{包名}_v1.0.bytes/.hash` 旧缓存 —— 因缓存路径含版本号，新版本写新文件，这些**不会被用到，无害**，只是排查时容易看花眼。
5. 🔴 **CDN 上仍是 404**：`curl http://106.52.92.221/CDN/PC/v1.0/{包名}.version` ×5 全返回 nginx 404（nginx 正常响应、`try_files` 生效 → 服务器侧配置没问题）。用户当时仍在 WinSCP 上传中，判定为**上传未完成**。传完后需复核；若仍 404 则是路径落错，文件必须在 `/var/www/kitchenchaos-cdn/CDN/PC/v1.0/`（**要含 `v1.0` 这一层**）。

## 排查「External Script Editor 设了 Rider，重开却变回 VS Code」

用户反馈：`Edit → Preferences → External Tools → External Script Editor` 选了 Rider，下次打开 Unity 仍是 VS Code。

### 已核实的本机事实（非猜测）
- **Rider 装在 `D:\JetBrains Rider 2026.2.3.1\bin\rider64.exe`** —— **不在 C 盘默认路径**，且目录名**含空格**。Unity 的自动探测只扫 `%LOCALAPPDATA%\JetBrains\Toolbox\apps\...` 与 `C:\Program Files\JetBrains\Rider*`，**扫不到 D 盘这份** → 下拉框可能列不出它，必须 **Browse** 手动指定。
- 项目**同时装了 3 个 IDE 集成包**：`com.unity.ide.vscode@1.2.5`（🔴 官方文档明确：该包已不再受支持、不应使用）、`com.unity.ide.visualstudio@2.0.28`、`com.unity.ide.rider@3.0.40`。
- 读 `Library/PackageCache/` 源码确认：**三个包都只 `EditorPrefs.GetString("kScriptsDefaultApp")`（读取），没有任何一处 `SetString`** → 排除「IDE 包把设置改回去」这一嫌疑。
- 注册表键 `HKCU\Software\Unity Technologies\Unity Editor 5.x` 的**属主 = `BUILTIN\Administrators`**；以**非提权**身份直接 `Set-ItemProperty` 写入该键**成功** → 单纯的文件/注册表权限不是瓶颈。
- 该偏好值位置 = 上述键下的 `kScriptsDefaultApp`（存编辑器 exe 全路径）。
- Unity **2022.3.62f3c1（中国版）**装在 `D:\UnityEditor`；Hub 在 `D:\UnityHubCN`；VS Code 在 `%LOCALAPPDATA%\Programs\Microsoft VS Code`。
- 工程根目录同时存在 `.sln` / `.slnx`(Rider 格式) / `.vscode` / `.idea` / `Unity.VSCode.Editor.csproj`。

### 根因与解法（社区公认，3 个独立来源一致）
> 来源：Unity Discussions 帖 846552「External Script Editor resetting to default on restart」（20+ 楼确认）、unity.huh.how、CSDN。

**用管理员身份启动 Unity Hub** → 打开项目 → 改一次 External Script Editor → 关闭 Unity 与 Hub → 再正常（不提权）打开。这一次写入才真正落盘，之后正常权限可保持。
判定依据：Hub 普通权限启动时，对该注册表偏好键的写入不落实 → 下次读回旧值/默认值（默认回落 VS Code）。

### ⚠️ 诊断副作用（需知悉）
- 向 `HKCU\Software\Unity Technologies\Unity Editor 5.x` 写入了一条测试值
  `kScriptsDefaultApp = D:\JetBrains Rider 2026.2.3.1\bin\rider64.exe`（**未清理** —— 它正是用户想要的值）。
- **Unity 当时正在运行（3 个 `Unity.exe`）**，退出时 EditorPrefs 回写可能覆盖该值 → 需按上述流程重做一次。

### 工具经验（下次直接用）
- 🔴 **PowerShell 工具的 stdout 不回传**（`"OK"` / `Write-Output` 均看不到）→ 必须 `Out-File` 到临时文件再用 Read 读取。
- 🔴 **`reg.exe` 被安全策略拦截**（Program Blacklist）→ 查注册表改用 PowerShell 的 `HKxx:` 提供程序。
- 🔴 枚举注册表值**不要**用 `(Get-ItemProperty $k).PSObject.Properties`（会误报 0 条）；用 `Get-ItemProperty -Name <值名>` 直读才准。

## 修复 HotUpdateBootstrap.cs 的编译报错（HybridCLR 加载器）

用户报「无法解析符号 HybridCLR」「无法解析符号 AotMetadataDlls」。排查后**实际共 5 处**（4 处编译失败 + 1 处运行时静默失效）。

### 修复清单（`Assets/Scripts/FrameWork/HotUpdate/`）

| # | 文件 | 问题 | 修法 |
| --- | --- | --- | --- |
| 1 | `FrameWork/LiteGameFramework.asmdef` | 缺 `"HybridCLR.Runtime"` → `using HybridCLR;` 报 **CS0246** | `references` 追加 `HybridCLR.Runtime` |
| 2 | `HotUpdateBootstrap.cs` | 数组声明拼成 `AotMetadateDlls`，使用处写 `AotMetadataDlls` → **CS0103** | 声明改名对齐 |
| 3 | `HotUpdateBootstrap.cs` | 常量声明 `codePackage`、使用处写 `CodePackage` → **CS0103**（用户未报但必然报） | 常量统一为 `CodePackage` |
| 4 | `HotUpdateBootstrap.cs` | 用 `YooAssetsLoad` 却没 `using LiteGameFramework;`（该类**在 LiteGameFramework 命名空间**下，非全局） | 补 using |
| 5 | `IHotUpdateEntry.cs` | 残留 `using dnlib.DotNet.Emit;`（**根本没用到**）→ 编辑器零报错、Player 编译期必挂 | 删除，全文件不留任何 using |

### 已核实事实（有代码/元数据为证）

- **`dnlib.dll` 是 Editor-only 插件**：`Library/PackageCache/com.code-philosophy.hybridclr@941bbc723a/Plugins/dnlib.dll.meta` 的 `platformData` = `Any: enabled 0（Exclude Editor: 0，其余平台 Exclude 全 1）` + `Editor: enabled 1`；且 `isExplicitlyReferenced: 0` → **编辑器编译期自动引用**，所以 IDE 与编译器都不吭声，只在 Player 编译（含 `Generate All`）阶段炸。与 `UnityEditor` 同类陷阱，但藏得更深。
- **`AOTGenericReferences.cs` 真实位置 = `Assets/HybridCLRData/Generated/`**（**不是**工程根的 `HybridCLRData/`）。工程根那份只有 `AOTDllOutput/`、`HotUpdateDlls/`、`StrippedAOTDllsTempProj/`、`hybridclr_repo/`、`il2cpp_plus_repo/`。
- **权威 AOT 清单 = 6 个**：`DOTween.dll` / `LiteGameFramework.dll` / `System.Core.dll` / `Unity.InputSystem.dll` / `UnityEngine.CoreModule.dll` / `mscorlib.dll`。
  - 🔴 **`System.dll` 不在清单里** —— 用户原清单多写了它。而本加载器把"读不到字节"当**致命错误**，多写一个没进包的 dll 会**直接中断引导**。"多加载不会出错"**有前提**，已在指南 §5.2 更正。
  - 🔴 名字是 `Unity.InputSystem.dll`，**不是** `UnityEngine.InputSystem.dll`。
- **`YooAssetsLoad` 完整签名**：`namespace LiteGameFramework` 下的 `class YooAssetsLoad : SingletonMono<YooAssetsLoad>`；单例 = 继承来的 `public static T Instance`；加载 = `public AssetHandle LoadAssetSync<T>(string location, string packageName = null) where T : UnityEngine.Object`（**实例方法，不是静态**）。
- **`AssetHandle : HandleBase : IEnumerator, IDisposable`** → `yield return handle` 成立；`Status`（`EOperationStatus`）在 `HandleBase` 上、`AssetObject` 在 `AssetHandle` 上。
- **`RawFileObject : ScriptableObject`**，在 `namespace YooAsset` ✓ 满足泛型约束。
- **`AddressByFileName` 规则 = `Path.GetFileNameWithoutExtension(assetPath)`**（`YooAssets/Editor/BundleCollector/DefaultRules/DefaultAddressRule.cs:27`）→ `mscorlib.dll.bytes` 的地址恰是 `mscorlib.dll`，与加载器请求串天然一致。
- **`BundleCollectorSetting.asset` 目前只有 5 个包**（UI / GameRoomScene / PlayerPrefab / GameScene / GameScene2），**`Code` 包尚未创建**；`Assets/HotUpdate/` 目录也**不存在** → 指南 §7 尚未落地。
- `GameEntry` 类型**全仓不存在**（热更入口未写）；`HotUpdateBootstrap` 也**无任何调用方**（AOT 侧常驻 MonoBehaviour 未接）。

### 设计决策：编辑器下跳过 AOT 元数据补充

① 段加了 `#if UNITY_EDITOR / yield return null; / #else ... #endif`。理由：编辑器跑 Mono(JIT) 无 AOT 裁剪，补元数据无意义；跳过可让编辑器迭代**不必先打 Code 包**。
🔴 **坑**：`Initialize` 返回 `IEnumerator`，若编辑器分支里**一个 `yield` 都没有** → 编译器按普通方法检查返回值 → **CS0161**。那个 `yield return null;` 不是凑数，是必需的。
