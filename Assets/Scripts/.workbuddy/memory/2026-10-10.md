## 实际部署踩坑：nginx `-t` 报断链（sites-enabled 软链指向不存在的文件）

- 用户执行 §5.2.5 的 `sudo nginx -t` 后报错：
  ```
  2026/10/10 19:21:27 [emerg] 53515#53515: open() "/etc/nginx/sites-enabled/kitchenchaos-cdn"
  failed (2: No such file or directory) in /etc/nginx/nginx.conf:61
  nginx: configuration file /etc/nginx/nginx.conf test failed
  ```
- **诊断定性：典型的"断链"（dangling symlink）**，不是 nginx 问题。关键推理：
  - `nginx.conf:61` 是 `include /etc/nginx/sites-enabled/*;`，是**通配**。若是目录为空，glob 匹配不到任何文件，nginx **不会**报出具体文件名。既然报出了 `kitchenchaos-cdn` 这个名字，说明**软链确实存在**；
  - 而 `open()` 返回 `ENOENT (2)`，对软链而言就是**目标文件不存在**；
  - 结论：**§5.2.4 的 `ln -sf` 执行成功了，但 §5.2.3 的配置文件根本没建成**。用户跳过了 5.2.3 的验证步骤。
- 三种可能的"没建成"根因（已写进指南）：① `sudo nano` 粘完直接 `Ctrl+X` 退出、**没按 `Ctrl+O` 保存**（追问 `Save modified buffer?` 时按了 N）；② `sudo tee` 的 heredoc **最后的 `EOF` 没单独成行/顶格**（和 `}` 同行或行首有空格），shell 一直等输入，命令压根没执行；③ 路径敲错（`site-available` 少 s、`kitchen-chaos-cdn` 多连字符）。
- **关键补充认知**：`nginx -t` 失败**不会影响正在运行的 nginx**（校验失败就没有 reload，nginx 仍跑旧配置），所以服务没挂，不必慌；但 **`-t` 没过之前绝对不能 reload/restart**。
- 修复路径：回 §5.2.3 把文件建出来 → 软链会自动生效（**无需重建**）；若 `sites-available` 里确实有文件但软链仍断（软链指向别处），才需 `sudo ln -sfn ...` 重建。

  - §5.2.3 的验证块升级为「**硬门槛**」，直接预警上述报错原文，并解释 `nginx.conf:61` + ENOENT 的正确读法；

## 实际部署踩坑（续）：本机 curl 报 `(28) 超时` → 安全组 80 未放行

- 用户执行 §5.2.7 本机自测，报：
  ```
  curl: (28) Failed to connect to 106.52.92.221 port 80 after 21042 ms: Could not connect to server
  ```
- **诊断定性：超时（error 28）= 报文被静默丢弃（DROP）**，等价于"安全组没放行 80"。依据是 §5.2.6 已建立的口诀：**超时 = 进不来（网络层被挡）；秒拒 `Connection refused` = 进来了但没人在（服务层没起）**。腾讯云对未放行端口是 DROP 而非 REJECT，所以"没开端口"表现为**卡住 21 秒**而不是立即报错。
- **与 7777 是同一类问题**（第三次复现同一根因）：`DEPLOY_Ubuntu.md` §1.3 记录过当时的实测 `22 → OPEN 0.01s`、`7777 → TIMEOUT 8.00s`、`65535 → TIMEOUT 8.00s`。
- **指南新增 §5.2.9「三层连通性定位法」**（本轮交付）：
  - 先给**报错对照表**：error 28 超时 → DROP → 安全组；error 7 秒拒 → 无监听 → nginx 没起；
  - **STEP 1 ☁️ 服务器**：`systemctl status nginx` + `sudo ss -tlnp | grep ':80'` + `curl -I 127.0.0.1/...` 三条，先把服务侧排除干净（三条都正常则问题 100% 在网络层）；
  - **STEP 2 ☁️ 服务器**：补查**本机防火墙** `sudo ufw status verbose` 与 `sudo iptables -L INPUT -n`（腾讯云镜像通常 inactive，但装某些软件会顺带启用 ufw）；

## 切到 HostPlayMode 后的补漏：UIConfig 读取路径两个缺陷（P0-10）

### 🟡 P0-10a：`ELoadResources` 失败以 `null` 回调 → UIManager 必抛 NullReferenceException
- 证据：`YooAssetsLoad.ELoadResources<T>`（`YooAssetsLoad.cs:584-628`）在 4 个失败分支（包不存在 `:590`、类型不符 `:618`、加载失败 `:624`）都执行 **`onLoaded?.Invoke(null)`** —— 即**失败也会回调，只是参数为 null**。
