## 端口不通的定位结论（21:14，决定性证据）

- 用户报 `警告: TCP connect to (106.52.92.221 : 7777) failed`。用本机 Python socket 做**三分组对照探测**：
  - `22 → OPEN 0.01s`（网络路径正常）
  - `7777 → TIMEOUT 8.00s`
  - `65535 → TIMEOUT 8.00s`（必然关闭对照组）
- **7777 与 65535 表现完全一致** → 判定为**包被静默丢弃（DROP）**，即**腾讯云安全组/防火墙未真正放行 7777**；与"服务有没有起"无关。用户此前在清单里勾掉第 1 项，**实测证明未生效，已退回未完成**。
- **这个判据要记住**：腾讯云对未放行端口是 DROP（客户端看到**超时**），而"已放行但无服务"由内核回 RST（客户端看到**立即被拒 / Connection refused**）。二者处置方向完全相反，不可混淆。已固化为指南 **§1.3「一分钟判定法」**。
- **SSH 认证实测**：`ssh -o BatchMode=yes ubuntu@106.52.92.221` 返回 `Permission denied (publickey,password)` → 本机 `~/.ssh/id_ed25519` **未授权到该服务器**，用户实际用**密码**登录。因此 `deploy.ps1` 默认的密钥认证路径**当前不可用**，需先上传公钥到 `~/.ssh/authorized_keys`，或改用手动 `ssh` 输密码。`known_hosts` 含该 IP（17:44）只证明主机密钥已接受（发生在认证之前），**不代表认证成功**。
